## Problem and current behavior

Inspected at `MachineWisdomAI/saga-a2ui@b1dd011bd4cf55e1ec0ba6ced7489c9354e3d851` (21 October 2026) and the Ansari Faithful Answers application (`app/ansari-faithful-answers`, 21 October 2026 revision `5acba0e`).

The React package stops at `A2uiSurface`, `FaithfulCardProvider` and `faithfulCardEntry`; everything above that is re-typed by each consumer. Hand-authored A2UI opening messages appear in the five maintained templates (`lit-node`, `lit-express`, `lit-fastify`, `lit-hono`, `lit-hapi`), three examples, `apps/lit-host` and Ansari; the `connectToolResultView` handshake (hold a result until ready, latest wins, retire before dispose, `pagehide`) in the five templates, three examples and Ansari; the policy-in-document transport and `createContentView` in four places each. `createA2uiAppElement` takes `initialInput: unknown`. Ansari styles 31 rules against `.saga-card` internals and walks the card's DOM to find its attribution paragraph, because the card promises nine CSS variables and no class names. The examples are labelled development checks, yet they are the de facto API: Ansari's `main.tsx` is 133 lines, about 25 of them its own decisions.

## Proposed behavior

Before, the application owns every ordering rule:

```ts before
const answer = openAnswerSurface(); // hand-written createSurface, updateComponents, updateDataModel
let ready = false, pending; // hold a result until the handshake and the fonts finish
window.addEventListener('pagehide', () => { retire(); connection?.dispose() ?? app.close(); });
```

After, a card application states only what is its own, importing from one package:

```tsx
import {FaithfulCardApp, startFaithfulCardApp} from '@saga-a2ui/react-mcp-stack/faithful-card';

const definition = FaithfulCardApp.define({name: BRANDING.name, version: APP_VERSION})
  .reader({dialect: 'commonmark-tables-strikethrough', maxLength: CARD_MAX_UTF16_UNITS})
  .policy('document')
  .result(value => {
    const parsed = answerEnvelope.safeParse(value); // the application's own Zod contract
    return parsed.success ? {markdown: parsed.data.answer, heading: parsed.data.question} : undefined;
  })
  .texts({waiting, problem, connectFailure, readyFailure, policyFailure})
  .build();

const view = startFaithfulCardApp(definition, {
  container: document.getElementById('root'),
  readyWhen: signal => loadKitab(document, signal),
  sizing: 'own',
  hostContext: (context, host) => applyAnsariTheme(document.documentElement, context, host),
  chrome: ({card, state}) => <AnswerView card={card} state={state} />,
});
await view.ready;
```

An own-catalog application uses the stack's main entry the same way; the starter template becomes:

```ts
import {defineSurface, startA2uiView, createLitActions, ActionButton, z} from '@saga-a2ui/lit-mcp-stack';

const layout = defineSurface({
  surfaceId: 'starter', catalogId: CATALOG_ID,
  data: z.object({headline: z.string()}), initial: {headline: ''},
  root: {component: 'Column', bind: {}, props: {children: ['headline', CLEAR_ID]}},
  components: [
    {id: 'headline', component: 'Line', kind: 'title', text: {path: '/headline'}},
    {id: CLEAR_ID, component: 'ActionButton', child: 'clear-label'},
    {id: 'clear-label', component: 'Line', kind: 'body', text: 'Clear the note'},
  ],
});
const view = startA2uiView({
  container, layout, catalog: starterCatalog,
  actions: createLitActions({attach: v => v.watchById(CLEAR_ID, ActionButton, h => h.bindAction('activate', clearNote))}),
  onToolResult: (result, {surface}) => surface.update({headline: headlineFor(result)}),
});
await view.ready;
```

`build()` validates once (identity, reader options, policy source, parse operation and every text, naming a missing field) and returns an immutable value. `start` returns the running view at once; `ready` settles after the embedded policy is read and valid, the MCP bridge has connected with handlers installed before `connect`, the negotiated host context is applied and `readyWhen` has finished. A result delivered earlier is held, latest wins, and is shown once after `ready`, with image consent revoked before each presentation. On host teardown, `dispose()` or `pagehide`, the stack retires the view before disposing the connection. A Lit card application uses the same definition with `@saga-a2ui/lit-mcp-stack/faithful-card`.

## Responsibilities and interfaces

Stack packages are the decision. `@saga-a2ui/react-mcp-stack` and `@saga-a2ui/lit-mcp-stack` each connect one renderer to one delivery; `@saga-a2ui/{react,lit}-a2a-stack` follow later. An application installs one stack plus its framework peers (`react` and `react-dom` for React, singletons; `lit` once `@saga-a2ui/lit` is published, the workspace layout until then) and imports from the stack only. Each stack has a components-free main entry (`startA2uiView`, re-exporting the own-catalog authoring surface: `defineSurface`, `SurfaceLayout`, core's Zod 3 as `z`, the renderer's action helpers and catalog types) and a `/faithful-card` subpath (`startFaithfulCardApp`, re-exporting `FaithfulCardApp`, `CardContent`, `RunningView`, `StartFailure` and the card stylesheet). `@saga-a2ui/components` and `@modelcontextprotocol/ext-apps` are regular dependencies of a stack, so one install suffices under a strict layout. Two footprints follow. An own-catalog application's installed tree includes components and markdown-it as declared dependencies, and that is the correct install result. Its emitted browser bundle and runtime import graph exclude them, because the main entry imports nothing from components; that property is qualified by inspecting the packed build output, separately from the install check. "Components-free" describes the main entry and the bundle, never the installed tree. Re-exports stay limited to the interfaces the qualifying consumers use. `@saga-a2ui/react` and `@saga-a2ui/mcp` stay independent of each other. This amends [package layout](../../packages/README.md): "the application connects them" becomes "a stack package connects them; the application installs one stack", and the own-catalog rule extends to stack main entries. The CLI's `--a2ui-stack lit-mcp` maps to `@saga-a2ui/lit-mcp-stack`.

## Failure and recovery

| Trigger | Outcome |
| --- | --- |
| Embedded policy absent, malformed or invalid | Absent means Standard with empty lists; otherwise `ready` rejects with kind `policy` and `texts.policyFailure` shows. No view mounts on a guessed policy. |
| Bridge connect rejects | `ready` rejects with kind `connect`; `texts.connectFailure` shows. |
| `readyWhen` rejects | Connection disposed; `ready` rejects with kind `ready`; `texts.readyFailure` shows, distinct from a connect failure. |
| Result delivered before `ready` | Held; a later result replaces it; the latest is shown once when ready. |
| Result unsupported (parse returns `undefined` or throws) or rejected by the card | The shown answer clears, `texts.problem` shows, image consent is revoked; a throw is also reported to `onError`; the next valid result recovers. |
| Ordinary data update on an own-catalog surface | Applied in place; the mounted controls, their bindings and focus survive; a rejected update changes nothing. |
| Host teardown, `dispose()` or `pagehide` | Retire (consent, host-context hook, unmount) once, before the connection is disposed; later results reach nothing. During startup this aborts the readiness signal and drops held results; `ready` rejects with kind `disposed` and shows nothing; a late readiness outcome never remounts, delivers or shows a failure. |
| Application callback throws | During startup: connection, listener and sizing cleanup completes, then `ready` rejects with kind `application`. After `ready`: reported to `onError(error, phase)` (default `console.error`); the rest of that event's work is skipped and whatever the callback already changed stays, since the stack cannot roll back application side effects (a throwing result map still clears the answer, shows `texts.problem` and revokes consent); a throwing `onTeardown` or chrome unmount never skips connection disposal. |
| Builder or start misuse (missing identity or text, unknown policy source, container missing or busy) | `build()` or `start` throws naming the field or `container-busy`; a running view is untouched. |
| Transport input unsupported (the four rejections named in layer D) | `embedContentPolicy` throws; nothing is served. |

## Consumer-driven E2 amendment

Before, the card stacks read a result through the definition's `structuredContent` parse and rejected an `isError` result unread. A rehearsal of a real consumer found that its protocol also accepts a text-only result, rejects an error result with that result's own text, and words its other rejections itself; the stacks showed `texts.problem` and an empty card for all three. After, four additions, each an option, with the approved behavior as the default:

| Gap | Amendment | Owner |
| --- | --- | --- |
| Whole-result reading | `startFaithfulCardApp(…, {classifyResult})` in both stacks: the application receives the result as delivered (`isError` included) and returns `{kind: 'content', content}` or `{kind: 'rejected', text?}`. A rejection shows its `text`, else `texts.problem`. The stack still owns clear and present, consent, link state and `onError` (a throw is phase `result`, rejects without wording, rolls nothing back). E1's neutral parser and defaults are unchanged. | The neutral outcome and its checking in `readCardResult` (components, no delivery named); MCP's `isError` and `structuredContent` default in `readStructuredResult` (`@saga-a2ui/mcp/view`); each stack renders the outcome |
| One-stack composition | Subpaths of each stack: `/content-policy` (`createContentPolicy`, `embedContentPolicy`), `/server` (`createServerBudgets`, `registerPublicOperation`, `operationViewFromHtml`, `viewUriForHtml`, `attachRequestLifetime`, `OperationView`, `RequestLifetime`) and, in the card entry, the host link (`useHostLink`, `bindHostLink`) and `readingProfile`. The server entry reaches no browser graph and the browser graphs no server module. No new package. | stack packages re-export their owners |
| Host reading | `readingProfile` also recognises the historical `HTMLFragmentWrapper` host name and a host-context `deviceClass` that is an Echo Show class (`echo_show`, `echo_show_15`; a whole underscore-separated word). Taken from a consumer's fixtures, not from new host evidence. The application maps the answer onto its own tokens; the renderer decides nothing. | `@saga-a2ui/mcp/view` |
| Content styling | `strong`, `em` and `hr` join the committed content elements. The card sets no weight, size or colour on `strong` or `em`; a closing strong footer inherits the footer's treatment; one divider remains possible. `data-testid` and `data-annotation` stay outside the contract. | components styling list; [styling guide](../../docs/faithful-card-styling.md) |

Verification outcomes. A synthetic envelope and synthetic wording stand in for the application's protocol; the SDK names none. Through each stack's real start and result interface: valid structured content gives its heading and Markdown; absent or `null` structured content with usable text gives an empty heading and the exact text, terminal newline included; neither, a malformed present envelope even beside usable text (wrong or missing version, a missing, non-string or empty answer, a missing or non-string question, a non-object), or an error result with no usable text shows the supplied wording; an error result reaches the classifier whole and is rejected carrying its own text, with no card and that text told to the chrome as the problem, even beside a valid envelope; the next valid result recovers from each of these, an equal answer presented again ends image consent and the link outcome, and a throwing classifier reports and shows `texts.problem`. A packed strict (pnpm) stack-only consumer type-checks all the new entries and resolves them inside the installed stack. A device host context maps to the application's 1.6 font-size token with no transform and no sideways overflow in Chromium, and the branded stylesheet is checked for strong at 700, right-to-left emphasis, one divider and a strong closing footer.
